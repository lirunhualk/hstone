# 酒馆战棋随从与酒馆法术数据快照

本目录存放由炉石客户端卡牌数据生成、可离线读取的确定性快照。它与
`lib/game/content.ts` 中的已实现玩法逻辑相互独立；快照中存在一张卡，
不代表它的全部效果已经由当前游戏引擎实现。

## 筛选规则

生成器按以下顺序筛选：

1. `isBattlegroundsPoolMinion === true`，避免把退环境、金色版或内部卡算入池。
2. 排除 CardID 以 `BGDUO` 开头的 29 张双人模式专属随从。
3. 保留单人模式活跃池中的等级 1 至 6 随从。
4. 等级 7 的 12 张单人模式特殊随从保留在来源统计中，但不进入普通酒馆快照。

原始活跃标记为 278 张，排除双人专属后为 249 张，再排除 12 张等级 7
特殊随从后得到 237 张。各等级数量为：

| 等级 | 1 | 2 | 3 | 4 | 5 | 6 |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| 数量 | 22 | 32 | 41 | 50 | 57 | 35 |

酒馆法术使用相同的固定来源，并按以下规则筛选：

1. `isBattlegroundsPoolSpell === true`。
2. 显式排除 `BG31_242`、`BG31_243`、`BG31_244` 三张需要队友的双人模式法术。
3. 保留单人模式等级 1 至 6 的普通酒馆法术，排除 4 张等级 7 特殊法术。

原始活跃标记为 72 张，排除双人专属后为 69 张，再排除 4 张等级 7
特殊法术后得到 65 张。各等级数量为：

| 等级 | 1 | 2 | 3 | 4 | 5 | 6 |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| 数量 | 8 | 6 | 16 | 16 | 14 | 5 |

快照记录全部 65 张法术的 CardID、费用、等级、中文文本及关联种族。当前这
65 张普通酒馆法术均已按完整规则接入，并会按酒馆等级、关联种族和共享池
余量进入商店。“身份揭晓”“稳健异变”和“冒牌的智慧之球”的英雄技能候选、
6 星到 7 星变形及 7 星有用刷新边界也已进入引擎与专项测试，不会把“只有卡面、
没有效果”的法术混入对局。

`races` 保存卡面的一个或多个种族，`associatedRaces` 保存无卡面种族但只在
相应种族环境中出现的支援关系。两者不可合并，否则双种族随从和中立支援随从
都会失真。

## 饰品快照

`battlegrounds-trinkets-36.0.3-247416.zhCN.json` 使用暴雪官网卡牌库确定
当前饰品池，再以同一个 HearthstoneJSON build 补齐 CardID、费用、层级、
简体中文说明和关联牌。官网响应固定为 213 件，其中 9 件明确标记
`duosOnly`，排除后得到 204 件单人饰品：98 件次级、106 件强效。

生成器同时固定并校验两个完整来源文件的 SHA-256。58 件带关联牌的单人饰品
全部能从 dbfId 解析到固定 build 的 CardID，没有用名称猜测。四个仍在当前池
中的旧本地 ID 继续沿用；另四个已退池 ID 只由运行时兼容层保留，不进入快照
候选。完整的双打排除清单和来源元数据均写入快照并由离线测试校验。

同一生成器还锁定镜匣的真实关联法术“复映透镜”，以及老旧烛台可发现的全部
消耗为 2 的时空扭曲随从：小型池 25 张（等级 3）、大型池 41 张（等级 5）。
这 66 张普通/金色实体的 CardID、dbfId、属性、种族、基础关键词和中文说明均
保留在快照中并接受数量与唯一性硬校验。运行时已准确注册这些实体和基础关键词；
各卡独有的复杂时空扭曲文字仍明确标记为部分支持，避免把尚未实现的文本宣称为
完整规则。

普通随从与法术数据中有 12 张简体中文说明把内部动态文本分支串接在一起。
对应快照保留客户端原始字段以便复核，`lib/game/content.ts` 则只对这 12 个
CardID 提供可读的普通版本说明，并由内容测试防止内部 `+X/+0` 模板再次显示
到界面。

饰品生成器会在导出时保留 18 张动态计数饰品的初始文案分支，避免把“初始
说明”和“剩余次数”状态首尾重复显示；另将 4 个由官方静态 JSON 暴露为
`92` 的运行时种族图标占位符转换为可读的“与你战队相符类型的随从”。这些
清洗只影响界面说明，不改变 CardID、费用、层级、关联种族或来源哈希。

## 生成和校验

联网下载固定 build 并生成：

```powershell
npm run data:bg:generate
```

也可以对预先下载的原始文件离线重建；生成器仍会校验同一个 SHA-256：

```powershell
npm run data:bg:generate -- --source C:\path\to\cards.json
```

完整性测试不联网，只读取已提交的 JSON 快照：

```powershell
npm run data:bg:check
```

饰品快照使用独立命令：

```powershell
npm run data:trinkets:generate
npm run data:trinkets:check
```

也可用两个已下载来源离线重建：

```powershell
npm run data:trinkets:generate -- --official-source C:\path\to\official.json --cards-source C:\path\to\cards.json
```

生成器对来源哈希、随从与法术总数、模式过滤、等级分布、唯一性，以及
36.0.3 的返场随从“鲜血精研者”和移除随从“睡梦织棘者”设置了硬校验。
更新版本时必须先核对官方补丁说明，再显式修改 build、哈希、预期数量和测试
哨兵；不要将来源改成会静默漂移的 `v1/latest`。
