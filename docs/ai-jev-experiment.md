# Jev 单席位决策对照实验

这项实验检验 TypeSafe Jev 能否改善当前本地 AI 的最终名次。它只在 headless 评测中替换一个席位，浏览器的七名 AI 仍运行 `video-strategy-v4-safe-recruit-health`。不因响应格式正确、模型高置信、夹具通过或几个样本名次改善就自动修改正式策略。

## 决策与引擎边界

- `scripts/ai-jev-client.ts` 只供服务器/CLI 使用，固定 `jev-1.13.0` 和官方 HTTPS API。它验证问题、模型版本、回答类型、概率分布和使用量，超时包含响应正文读取；未知使用量的失败会停止后续请求，不自动重试。
- `scripts/ai-jev-policy.ts` 给模型提供经过审计的己方观察、公开信息、亲自交手时看到的旧阵容、固定版本卡面和英雄/饰品/事件说明。模型看不到 seed、RNG、共享池数量、对手当前隐藏手牌/商店/战队、运行时实体 ID 或动作令牌。
- 引擎先执行原有洗牌，再完成受控席位之前其他 AI 的招募，暂停在该席位的真实出手点。模型选出的动作仍由原 reducer 执行；结束后按原顺序完成剩余 AI、回合结束效果和战斗。未覆盖时与正式策略逐字段相等，避免改变招募顺序造成虚假的改善。
- 每次动作执行后重新观察，不在克隆上试探刷新、发现、随机战吼或战斗的未来结果。只允许确定性动作的本地公开评分增量进入输入。
- 合法动作继续经过正式 v4 生命保护。刷新次数使用现有 profile 限制；每回合最多 50 次模型决策，冻结最多一次、换位最多两次，并检测循环、过期回答与拒绝动作。

候选列表在调用前由固定本地规则保留每类动作、合法结束选项，再补充到最多 12 个动作。它涵盖买牌、卖牌、出牌、法术目标、磁力、升本、刷新、冻结、发现、英雄技能及有限换位，但不是穷举所有完整交易序列。每次请求把即时战力、长期成长、经济和核心保留拆为四个独立 Choice 问题，在代码里按 `0.40 / 0.25 / 0.20 / 0.15` 合并偏好。执行门槛使用已验证概率向量按实际总和归一化后、依官方公式 `(最大概率 - 1 / 选项数) / (1 - 1 / 选项数)` 计算的加权置信度，至少 `0.65` 才执行；供应商原始置信度仍保留供审计，不直接控制动作。这些分数和置信度均不是战斗胜率或吃鸡概率，也没有在战棋数据上完成校准。

输入省略为零的计数、为假的关键词、空集合和空可选值，并明确告诉模型这些默认语义；完整说明、牌区顺序、资源与索引仍保留。若保守输入预留仍超过单次 32,000 上限，则在联网前记为 `input-limit` 并使用本地策略，不截断卡牌效果。这是固定策略的覆盖边界，应与模型实际干预数量一起检查。

模型可以弃权并使用现有策略完成剩余招募；低置信、异常、预算耗尽和过期结果同样回退。若已经打开人类式待处理发现而模型失败，先用有上限的“第一个合法选项”应急解开，再回退；报告把这些动作单独记为 `emergencyChoiceActions`，不冒充正式策略或模型决策。模型主动结束时保留其站位；使用正式策略回退时沿用原来的站位调整。

## 两个候选方案

`all-decisions` 在每个有多个候选动作的受控局面请求 Jev，执行一个动作后重新观察。强制选择无需联网，模型可以随时弃权。

`critical-decisions` 只在以下固定检查点请求：有多个合法选项的待处理选择、可以升本、或满场且存在买牌/上场/磁力与出售取舍。其他状态由正式策略完成本回合剩余招募。因此它是检查点干预，不是逐条拦截正式策略内部的所有买卖决定。

这些条件、候选剪枝、权重和阈值都应在揭示新种子结果之前冻结；修改后必须使用新种子，不能在失败种子上调参宣布胜出。

## 凭据与预算

在本机环境变量或仓库内 Git 忽略的 `.env.local` 中自行配置 `TYPESAFE_API_KEY`。不要把密钥放进聊天、命令行参数、源码、报告、截图或前端存储。CLI 只读取这一个允许的变量，不执行 env 文件；Windows 会依次读取当前进程、当前用户和系统级的同名环境变量。

默认首次筛选最多 2,000 次请求和 1,000,000 个保守输入 token 预留单位，每次最多 32,000，单次超时默认 5 秒。预留算法使用 UTF-8 字节数加额外开销，没有官方 tokenizer；预留从不退回，报告会分开显示预留与 API 返回的实际已知使用量。未知使用量的失败可能仍计费，不能把已知 token 为零解释成零费用。请求次数是硬上限；预留单位不等同于供应商账单保证。

这套初始预算通常不足以完成完整 development 设计。CLI 允许显式增加到最多 100,000 次请求和 100,000,000 预留单位，预算扩大必须由运行者明确提供参数；默认值不会自动提高。先用联网 smoke 实测输入规模、响应质量和延迟，再决定较大实验预算。

## 运行

离线基础设施验证不需要凭据，不发送网络请求。每次尝试必须用新 seed 和新的 run ID：

```powershell
npm run test:ai-jev
npm run benchmark:ai-jev -- --mode fixture --preset smoke --start-seed 96120001 --run-id fixture-smoke-96120001 --max-input-tokens 8000000
```

`fixture` 使用明确的合成模型回答，报告标为 `fixture-infrastructure-only`。它只检验完整游戏、真实动作、回退、记录和报告流程，不能证明 Jev 的出牌水平或实测 API 延迟。

配置凭据后，先用独立种子做真实 smoke：

```powershell
npm run benchmark:ai-jev -- --mode jev --preset smoke --start-seed 96200001 --run-id jev-smoke-96200001 --env-file .env.local
```

完整 development 在两个场景 `neutral-v1`、`live-lobby-v1` 中运行 8 个物理席位轮换和 7 种 profile；每局候选只替换一个席位。每个 seed 有 16 局共用的正式策略 baseline 和 224 局候选。`--seeds` 接受 1 至 8；至少两个完整 seed cluster 才可能形成可用的开发证据。较大预算的示例需要运行者明确选择，并仍可能提前耗尽：

```powershell
npm run benchmark:ai-jev -- --mode jev --preset development --start-seed 96300001 --seeds 2 --run-id jev-development-96300001 --max-requests 20000 --max-input-tokens 100000000 --env-file .env.local
```

所有入口先校验现有中央 seed ledger，拒绝已消费、封存或未获授权的预留区间。本实验还在固定的 `outputs/ai-jev/development-seed-ledger/` 为每个 seed 创建不可覆盖的本地消费记录；fixture 和 jev 共用该目录，换 run ID 不能复用种子。中断、失败或零输出都不释放已经领取的种子。该本地记录只在当前工作区生效，跨机器/工作区前必须保留并核对消费记录。文档中的示例区间不是预留授权，实际运行仍以 ledger 为准。

## 报告与验收

报告位于 `outputs/ai-jev/<run-id>/report.json`，每个游戏结束后更新；每次模型决策的公开输入、问题、响应、请求哈希、选择和状态另外写入 `decisions/*.jsonl`，便于复核与离线重放。它们均被 Git 忽略。代码、内容、profile、协议参数哈希在运行前后核对，漂移会让证据失效。

比较使用相同初始状态和相同 seed 的配对结果。第一次模型动作改变之后，不声称候选仍拥有与 baseline 相同的随机轨迹。报告应检查最终名次、前四率、吃鸡率及其差异，按 seed 聚类计算区间，并按 profile、场景和物理席位检查退化；一颗 seed 的 smoke 不报告推断性置信区间。

同时检查真实执行动作数量、应急选择、回退原因、拒绝动作、过期响应、回合动作上限、截断、失败、API 延迟 p95、已知 token 与保守预留。缺失配对、未完整结算、模型或预算中断、技术异常、来源漂移、出现应急选择或某个候选方案零干预，都不能形成完整候选比较的可用证据；零干预不能称为提高了强度。

`promotionAccepted` 始终为 `false`。开发诊断只用于筛除候选和确定下一步；若显示稳定改善，仍需冻结策略、使用另一个独立确认集，并通过现有项目的推广门槛后才能修改浏览器中的默认 AI。

官方接口与语义参考：[API](https://docs.typesafe.ai/api)、[模型版本](https://docs.typesafe.ai/models)、[原子问题](https://docs.typesafe.ai/primitives)、[置信度](https://docs.typesafe.ai/confidence)。

## 2026-10-10 验证记录

离线 smoke `fixture-smoke-96120002` 已完成双场景 6/6 局、49 次合成回答、2 次实际模型路径动作，无拒绝动作、过期响应或回合动作上限触发；这些数字只证明基础设施可运行。此前 `96120001` 暴露的单次输入预留超限已通过默认值压缩和联网前 `input-limit` 回退修复，该失败种子仍保持消费状态。

已使用本机配置的凭据尝试真实 smoke `jev-smoke-96200001`。首次决策请求被 HTTP 拒绝，客户端在一次请求后停止；只读模型列表接口进一步返回 HTTP 451。没有任何成功 Jev 回答，真实报告为 incomplete，可能计费但未知使用量的请求计为 1。没有据此认定模型改善、扩大预算、重试或更改正式 AI。需要先恢复正常 API 访问，再以新的种子和 run ID 执行后续实测；原尝试的 seed 不可复用。

后续排查确认 451 正文为 `Typesafe is not available in your region.`，响应头为 `Server: cloudflare`、`Content-Type: application/json`。这是服务端对当前请求来源的地区访问拒绝；官方公开 API 文档尚未提供支持国家列表，因此不能仅凭这条响应断言某个特定国家的所有用户都不能访问，也尚不能验证密钥本身是否有效。接口地址和 Bearer 鉴权格式符合官方文档。

HTTP 451 现在会在客户端说明“服务访问受限”，评测报告保留 `provider-access-restricted-http-451`，CLI 会显示具体失败原因，并继续停止后续请求。更改模型名或重复请求不会解除服务端访问限制，但还应核对请求是否遵循用户已有的正常网络配置。只有正常网络配置仍被拒绝时，才需要 [TypeSafe 官方支持](https://typesafe.ai/legal/mca) 核实地区/账户资格或来源地区误判。

## 2026-10-11：系统代理修复与真实模型验证

进一步检查确认 Windows 系统代理已经启用，但 Node 默认不会读取该设置，当前进程也没有 HTTP(S) 代理环境变量。因此之前的请求实际走了直连路径，触发 TypeSafe 的地区规则；不能据此认定用户的正常网络路径也不可用。

`npm run benchmark:ai-jev` 和新的 `npm run diagnose:ai-jev` 现在都通过 `scripts/run-ai-jev.mjs` 启动。优先遵循显式进程代理；没有时，在 Windows 上读取已有的本机回环代理并仅传入子进程环境，使用 Node 原生 `--use-env-proxy`。不修改系统设置，不切换代理出口，不记录代理 URL，不关闭 TLS 校验，也不在失败后改走直连重试。PAC、需要代理认证或无法安全处理的配置会给出明确错误。代理模式需要支持该原生开关的 Node 24.5+；fixture 与帮助命令不读取系统代理。

只读模型列表已从 HTTP 451 恢复为 HTTP 200，返回 `jev-latest`、`jev-preview`。正式实验仍固定使用 `jev-1.13.0`；官方说明版本 ID 即使不出现在模型列表中也可调用。一次有上限的小型真实推理已成功，响应模型为 `jev-1.13.0`，已知输入/输出 token 为 `355 / 31`。这证明 API 与客户端可以工作，不代表战棋强度已提高。

```powershell
npm run diagnose:ai-jev               # 只读模型列表，不执行推理
npm run diagnose:ai-jev -- --inference # 额外至多一次小型、受预算约束的真实推理
```

诊断只保存状态、公开模型名、使用量和网络配置来源，写入 Git 忽略的 `outputs/ai-jev/access-diagnosis-current.json`。凭据、代理地址和供应商任意错误正文均不写入。后续正式对照仍须用新种子、新 run ID 和独立预算，不能复用此前失败尝试。

真实对局另外暴露了输出精度边界：56 个成功 Choice 概率向量均落在 0.01 网格，之后一个完整的 13 选项向量合计为 0.99，被原来的 0.005 容差拒绝。客户端现在只对“全部原始值为两位小数、选项齐全、每项有限且在 [0,1] 内、总偏差不超过 min(0.02, 选项数 × 0.005)”的 Choice 向量接受舍入误差，并记录原始总和、数量和精度。原始概率仍完整保留；策略组合各维度时按该向量实际总和归一化。缺项、越界、非网格的小偏差、明显错误和非最大值选择仍拒绝，Score/Noul 校验不变。实验策略版本更新为 `jev-visible-recruit-v2-rounded-probabilities`；推广门槛与正式七席策略均不变。

修复代理与舍入后，新的 `jev-smoke-96200006` 已完成正式策略 baseline 与逐次决策候选，随后在关键检查点候选中停止。共取得 18 次有效真实回答，观察到的 API 延迟 p95 约 504ms；本次没有高置信模型动作覆盖，不能认定出牌水平提高。停止原因是 `choice-argmax`：返回的 Choice 选择不满足官方“最高概率选项”语义，属于响应一致性问题，已经单独记录并保留拒绝。报告仍为 incomplete，不复用该种子、不继续盲目重试、不修改推广门槛。HTTP 451 已解决，但完整强度对照尚未完成。

## Review 后的实测预案

策略冻结为 `jev-visible-recruit-v3-derived-confidence`，保留 0.65 门槛及 Choice 一致性校验。通过 review 和完整检查、发布代码后，依次使用新种子 `96320001` 至 `96320004` 做四个独立真实 smoke；每次最多 100 个请求、2,000,000 保守输入预留单位，单次超时 15 秒。先核对 seed ledger；已消费种子不替换重跑。完整计划共 24 局，覆盖两种场景、两个候选方案，限定 balanced 风格与物理席位 1。

汇总预先按 seed 聚类，每个候选方案每 seed 有两组配对；报告平均名次、前四率、吃鸡率、差异区间、模型实际动作及失败。若首个新种子再次出现供应商契约拒绝，停止整个批次并报告不完整结果，避免用重复请求撞过同一错误。该规模只提供探索结果，`evidenceUsable` 和 `promotionAccepted` 继续为 false；不得从有限席位与风格推广至全部 AI。
