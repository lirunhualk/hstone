# 七名 AI 的视频观察策略

本项目不会在游戏运行时访问 Bilibili，也不会把视频、截图或玩家身份数据打包进游戏。实现方式是人工复核公开教学与实战视频，把反复出现的决策原则整理成离线、确定性、可测试的权重和规则。这样在 Surface 上断网也能运行，相同种子与相同行动仍会得到相同结果。

这些内容是对公开视频的观察以及由此形成的工程推断，不是暴雪官方规则。具体卡牌、饰品和伤害保护机制会随补丁变化，因此只提取“节奏、经济、成长、三连、转型、循环位、站位”等跨版本原则，不照搬旧版本数值。

## 2026-08-08 当前部署状态

正式七席当前共同使用 `AI_POLICY_VERSION=video-strategy-v4-safe-recruit-health`。v4 的已部署改进是规则级生命安全守卫：“夜鬼淘金”式英雄技能偷取酒馆牌并直接扣除 2 点生命前，先拒绝会穿过安全底线的激活；招募阶段打出随从前，投影直接英雄伤害、`afterFriendlyPlayed.heroDamage`（按引擎的金色组件倍率）、普通 `damageHero` 战吼（按实际战吼触发次数，含本回合尚未消费的 `War Drum`）及 `BG26_525` 交互战吼（按其 golden repeat）的发现等级伤害。守卫把护甲计入可承受量，并按每个 profile 的健康底线保守持牌；当前场面或即将打出的随从自身能回溯伤害时，则按真实执行顺序放行观察者例外。七种软偏好都不能绕过这些共享边界。

本轮还把 7 个 runtime-compatible Bilibili 来源整理为 `60` 个严格窗口、`64` 条宏观样本：`upgradeNow=12`、`defer=10`、`refreshOnce=11`、`stop=10`、`freeze=10`、`unfreeze=11`。直接标签要求画面明确显示目标选择；推断 `defer` / `stop` 必须由目标动作之外的一次可见操作把金币从合法推进到立即不合法，并机器记录前后金币与所需费用；推断 `unfreeze` 只接受招募到战斗的阶段边界，刷新动作本身不能标成 `stop`。每个窗口绑定 BVID、时间点和复核媒体 SHA-256。`35.4.2` 只保留宏观 UI、金币合法性与阶段边界，排除卡牌数值、英雄、饰品和异常规则；`36.2` 来源仅作 evidence，不进入当前固定运行时的训练。

三折逻辑回归 artifact 虽然结构有效，但 upgrade、refresh、freeze 三个头的离线 `qualityPassed` 全部为 `false`；视频又没有配对 legacy baseline，所以整体 promotion gate 同样为 `false`。候选未部署，也没有继续运行研究模拟或正式 `304` / `305`。两段正式区间 `30_400_001–30_400_064`、`30_500_001–30_500_096` 已在 seed ledger 中封存，所有 benchmark 入口都必须在开始运行前拒绝。完整指标与 artifact、runtime payload、dataset 哈希见 [`ai-learning-roadmap.md`](ai-learning-roadmap.md)。这里的结论只适用于本地语料与模拟器，不能宣称真实天梯强度已经提高。

确定性公开视频规则 `video-residual-buy-spike-before-level` 也没有因“可解释”而直接上线。它在开发种子 `91_000_001–91_000_004` 的双场景、八轮换成对诊断中覆盖 `175` 次，`128/128` 次运行完整，但平均名次只改善 `0.017857`，95% seed-cluster 区间仍跨零，且对子与健康升本 profile 明显变差。因此流程在 4-seed 诊断停止，没有追加到 24-seed 门禁；完整区间和分项结果见路线文档。

后期高本 surplus 升本候选在 `92_000_001–92_000_004` 的 `128/128` 局中覆盖 `47` 次，平均名次差 `-0.0513`、95% 区间 `[-0.1775, +0.0749]`，同样因证据不足而在 4-seed 阶段停止。随后用 `92_100_001–92_100_008` 建立的 64 局当前 v4 绝对基线显示，powerLevel 的平均名次/前四率/吃鸡率为 `5.0000 / 0.3125 / 0.0781`，deathrattle 为 `4.5469 / 0.5156 / 0.0625`；这些小样本只用于定位下一候选，不能宣称 profile 间存在已证明的强弱差。

本轮还实现并审计了仅限 headless 的 `sell-one-v5` 原子换将候选：满场、手牌不超过 8 张、锁定报价恰差 1 金、最弱来源实际售价为 1 且没有出售副作用时，先在完整克隆上出售，重新核验报价与 profile 替换分差，再购买同一实例；成功后才原子安装，失败不改变原状态。普通 `advanceHeadlessGame` 和线上 v4 不会启用它。最终 `92_240_001–92_240_008` 完成 `1,024/1,024` 个运行、`896/896` 个焦点 pair，产生 `271` 次严格闭账的出售购买决策，且零失败、平局、截断、哈希漂移或出售后异常。总体名次差 `-0.071429`、95% 区间 `[-0.129119, -0.013738]`，但没有达到预注册的 `-0.10` 最小改善；magnetic 的名次与前四率分组门槛、tempo 的前四率分组门槛也失败。因此结果是 `accepted=false`，不扩到 24 seed，不解封 `304` / `305`，生产策略继续保持 `video-strategy-v4-safe-recruit-health`。完整安全条件、账本和分组结果见路线文档。

后续 `sell-one-v6-settled-warband` 没有按旧结果挑选 profile，而是在同一原子克隆中把购买后的手牌动作结算完，再要求整队总分至少提高原 profile 已存在的 `replacementMargin`；v5 模式继续保留以复现历史证据。预注册的全新 `92_300_001–92_300_008` 同样完成 `1,024/1,024` 局和 `896/896` 个 pair，零失败、平局、截断、哈希或诊断账本问题。它在 `1,112` 个 eligible 机会中接受 `244` 次、以局部分差拒绝 `850` 次、以整队守卫额外拒绝 `18` 次；七个 profile 都有真实分叉。总体名次差只有 `-0.032366`，区间 `[-0.086488, +0.021755]`，tempo / triple 的名次均值仍退化 `+0.007813 / +0.015625`，且三个分组比率门槛失败。因此 8-seed 筛选已否决，预留的 `92_310_001–92_310_024` 不运行并保持 sealed，候选不部署。这个结果说明整队复核能过滤部分 magnetic 风险，但单条全局换将规则仍不足以同时提高七席；下一学习主线应转向单焦点 profile 的约束式参数进化，再以七次单焦点因果评测和一次联合 roster 评测共同晋级。

单焦点 cooperative categorical CEM 的 training 与 independent selection 均已完成。training 只搜索 `player-5 / powerLevel` 的四个字段，32 个候选槽位在 fresh registered run 中选出 `-1 / 14 / 3.5 / 2`；8-seed training 的总体名次差为 `-0.002232`（95% 区间 `[-0.023254,+0.018789]`），powerLevel 名次差为 `-0.15625`（`[-0.383186,+0.070686]`）。随后冻结的 `93_100_001–93_100_024` selection 完成 `768/768` 局和 `2,688/2,688` 个 pair，runner failure、截断、平局、缺失配对和 provider error 均为 `0`，所有 provenance 前后稳定，结果可信但 gate rejected。

selection 的总体名次/前四/吃鸡差分别为 `-0.00409226`（`[-0.01652328,+0.00833876]`）、`-0.00037202`（`[-0.00502090,+0.00427686]`）、`+0.00334821`（`[+0.00148341,+0.00521302]`）。powerLevel 三项分别为 `+0.09635417`（`[-0.01149406,+0.20420240]`）、`-0.02343750`（`[-0.04781986,+0.00094486]`）、`-0.00520833`（`[-0.02710899,+0.01669232]`）。精确三条否决理由是：powerLevel 名次均值没有达到 `<= -0.10` 且点估计反向；名次区间上界没有 `< 0`，不能排除退化；前四率区间下界没有达到 `>= -0.02` 的非劣底线。总体吃鸡率的正向点估计不能覆盖这些事前固定的焦点失败。

这次反转明确按过拟合处理。training 的 8 个 seed cluster 有 `7/8` 显示 powerLevel 名次改善；selection 的 24 个 cluster 却只有 `5` 个改善、`4` 个持平、`15` 个恶化，而且 `neutral-v1 / live-lobby-v1` 的名次点估计都恶化，分别为 `+0.08854167 / +0.10416667`。因此不得回看 `93_100` 后继续调 powerLevel、补样或重跑，也不能把单焦点 training 外推成七名 AI 已提高。

下一轮以七 profile 为共同学习对象：用共享的 `4` 个小步长 delta 覆盖七档，严格分离全新 training 与 validation；training 只运行 joint roster，冻结后的唯一候选才在 validation 中运行一次 joint intervention 和七次 single-profile intervention；joint 的七档与每个 single 的焦点档都必须观察到真实决策分叉，零暴露不能冒充非劣；目标采用七 profile 宏平均、风险调整后的最差 profile 和逐 profile 非劣约束，不能用局部大收益抵消可靠退化。`93_300_001–93_300_016` 与 `93_310_001–93_310_024` 目前只是在文档中的拟议 development / validation 命名区间，尚未进入 ledger、未 reserved、未注册且从未运行，本文不授权执行。

v4 本身也完成了单座位反事实诊断，而不是把安全直觉当成强度证据。开发种子 `90_040_001–90_040_004` 的双场景中，每个场景先跑全 `legacy-v3`，再逐个只把七个正式物理座位之一切到 `safe-v4`；`64/64` 局、`56/56` 个原始 pair 和 `28/28` 个 seed/profile 逻辑配对全部完成，无失败、截断或平局。三项结果差均为 `0`，95% seed-cluster 区间均为 `[0, 0]`。受控座位的 `33` 次随从自伤候选中，`31` 次被真实伤害回溯豁免，另外 `2` 次仍高于底线，因而没有一次 v3/v4 实际决策分叉。该结果只支持“这四个自然 seed 中守卫没有副作用且没有 treatment exposure”，不支持“已经提高胜率”；所以不扩大到 24 seed。守卫继续作为 hard safety invariant 保留，未来基准必须观察到 legacy 原本要执行的下一动作确实被 v4 改写，才可能通过 screening gate；仅过滤本来不会选中的危险牌不算暴露。用于对照的 v3 override 只存在于同步 headless 克隆内，并以 state identity、canonical 八座位校验和 `try/finally` 隔离，普通游戏无法关闭 v4。

所有偏好都是软权重，不是强制流派。若另一张牌提供显著更高的即时战力，七名 AI 都会放弃人设偏好；低血或场面严重缺员时也都会优先保命。

## 已编码的决策

- 升本会同时检查当前等级、金币、有效生命、目标场面数量、商店最佳牌相对战队最弱牌的提升，以及各策略的风险边界。购买经济牌或法术后会重新评估，而不是只在回合开始判断一次。亡语策略的“改走常规曲线”候选已进入自动评测，但在严格留出门禁接受前仍保留已发布的慢一回合偏好。
- 低于策略安全血线且战队仍有明显弱点时，如果升本后连 3 枚购买金币都无法保留，AI 会把金币留给刷新和补强；若当前最弱随从也已达到本等级的稳健战力线，仍允许承担风险升本。该规则把“低血”与“弱场”同时作为条件，不会把所有低血局机械地锁死在低本。
- 随从评分拆分为身材、圣盾/复生/烈毒/顺劈等即时战力、当前种族协同、战吼与亡语引擎、经济效果、磁力目标、对子和第三张价值。给场上或手牌实体评分时会先排除这张物理牌自身，只有真实的另一张副本才形成对子；普通金色牌和将被立即吸附的磁力牌不会获得无法兑现的三连分，金色惊喜元素的通配再三连语义仍保留。
- 随从与酒馆法术按费用效率统一比较；强法术可以优先于普通随从，但第三张和显著场面提升会阻止盲目买法术。
- 满场时会比较替换收益，手牌中足够强的非磁力随从也能替掉弱牌；通过门槛后会先买下经过认证的同一商店报价，再在最新状态上完成替换，不会出售后因协同重排改买另一张未验证报价，也不会因出售触发填满手牌而永久缺员。
- 刷新次数、最后一枚金币与免费刷新会按策略和场面使用；冻结同时检查随从、强法术、对子和三连机会。
- “时间管理”在弱场或低血时选择立即战力，安全时才选择下回合的延迟收益。
- 站位会把需要先死的亡语放在引擎之前、保护布莱恩/提图斯类辅助。连续遇到同一对手时，只用上一次本人实际交手所记录的阵容快照识别圣盾嘲讽与顺劈，选择破盾单位和隔离缓冲位；不会读取对手本回合招募后的隐藏阵容。
- 龙体系会按当前龙数量和已积累的开战增益评估火铸唤魔师；场上存在唤魔师时，每张酒馆法术会额外计入永久成长价值。最终站位会把一个或多个执念诗心龙串在最高价值的龙之间，使相邻保护尽可能覆盖两个目标。
- 鹦鹉会获得与当前可触发亡语价值相关的额外评分；最终站位把普通或金色鹦鹉放在攻击序列最前，并把评分最高的可用亡语紧接在其后。该调整只改变战前站位，不为 AI 偷看随机结果，也不会绕过与玩家共用的亡语、提图斯、召唤空间和死亡波结算。
- 食客会比较两个可复核分值：即时分只计算手牌实际容纳的 4/8 张，并乘当前测绘员完整施放次数、单个最佳鲁古格转投数和当前宝石属性；永久分计算现有/近期明确可得手牌宝石以及作曲鬃师下一场一次保守复仇的预计应用次数。低生命只给即时分节奏加权，平分固定选永久成长；选择属于随从抉择，不会误用布莱恩倍增。测绘员在零宝石且没有近期来源时不再获得虚假专属分，鲁古格必须有合法非鲁古格友军才计算转投，作曲鬃师的战斗宝石不会被测绘员错误放大。AI 使用手牌宝石时会优先选择可兑现转投的鲁古格，所有派生宝石仍走玩家相同的逐颗规则，不会递归放大。

## 可重复全大厅评测

`scripts/benchmark-ai.ts` 可以在不启动浏览器的情况下运行真实 8 bot 完整大厅。每个基础种子都会把七种正式策略和一个不计分的 balanced sparring control 轮换到全部 8 个物理席位；完成局报告平均名次、前四率和吃鸡率，同时保留第 3 回合场面、平均剩余金币、升本频率和低血升本比例等诊断项：

```powershell
node --experimental-strip-types scripts\benchmark-ai.ts --seeds 10 --start-seed 7001 --max-rounds 40
```

引擎现提供 `createHeadlessGame` 与 `advanceHeadlessGame`：8 名玩家都走同一 AI 招募、站位、战斗和淘汰链；`player-0` 淘汰后对局仍继续，输入状态不被修改，相同种子逐字节可复现。基准不再保留 999 血假人，也没有人为 bye。它仍是本地模拟器内的相对自博弈，不能外推为真实天梯胜率；当前中性环境也尚未自动选择英雄、饰品和异常。达到最大回合的对局会明确计为截断；逐局记录保留已淘汰目标的精确名次，并只把仍存活目标表示为 `[1, 存活人数]`，不会伪造最终排名。结果还带内容版本、策略版本、完整策略哈希和 evaluator 源码哈希，长跑时会按 seed 输出进度。

`scripts/search-ai-policy.ts` 在这个基准上对单个策略参数做只读坐标搜索。候选权重只在同步回调内生效，异常、异步误用和嵌套覆盖都会安全恢复或拒绝；训练/留出种子强制不重叠。默认 8 个训练 seed、24 个独立留出 seed、每个 seed 8 席位轮换，并同时报告精确名次比较和候选最坏/基线最好区间：

```powershell
node --experimental-strip-types scripts\search-ai-policy.ts --strategy deathrattle --parameter upgradeRoundOffset --values 0,1 --incumbent-value 1 --train-seeds 8 --holdout-seeds 24 --max-rounds 100
```

动作级学习使用 `AiTrainingEnvironment`：一个受控席位通过隐私安全 observation、区域/索引描述和当前状态版本有效的 opaque action token 操作，其他七席仍走现有 AI；`END_TURN` 会完成其余招募与本轮战斗，`CONTINUE` 进入下一招募回合。默认训练 mask 仍由真实 reducer 裁决；planner mask 则复用引擎的购买费用、刷新报价、目标集合、容量和磁力查询，和 reducer mask 做逐动作等价测试，避免为每个候选克隆完整八人状态。每个动作还公开可见费用和保守的 planner disposition。购买、出售、打出、施法、升级、刷新和选择都先作为“执行当前动作后重规划”边界；planner API 在执行前只返回动作，不返回 fork、随机结果或执行后 observation。只有冻结切换等预先证明不会消耗 RNG 的动作才允许反事实展开，一旦实际跨过 RNG 就触发不变量错误。观测显式排除共享池、对手当前私有区域、其他对局战斗详情和 runtime ID，只保留本人状态、公开大厅信息及本人合法见过的对手快照。

`scripts/ai-legacy-expert-rollout.ts` 复用同一个安全边界，把七席现有规则在升本、单次刷新和冻结处的 `legacyChoice` 与 `legalChoices` 记录成深冻结专家轨迹。recorder 永远弃权，不会改变动作；隐私 bundle 不含 seed、RNG、共享池和运行时 ID，并带 context/content/policy 版本、七个 profile、计数、聚合评测摘要和 canonical SHA-256。原始 benchmark 结果单独返回，不属于可训练 bundle。该轨迹可用于先训练一个模仿 legacy 的三头分类器，再只对与人工视频标签一致且置信度至少 `0.90` 的少量分歧做 residual 候选评测。

## 可重复性与验证边界

AI 继续复用玩家相同的购买、出售、升级、三连、施法、磁力和战斗结算函数；策略层只负责评分和选择，不另造一套规则。策略本身不引入网络请求或新的随机源，接近同分时仍由现有确定性顺序解决。

自动化测试覆盖七种唯一映射、健康/低血升本分歧、动态亡语升本曲线、软流派偏好、明显战力差覆盖偏好、已持有实体的对子自排除、普通金色与磁力吸附边界、惊喜元素通配再三连、满手牌下认证报价的安全替换、残差上下文隐私与原子回退、三个宏观覆盖边界、顺劈防护站位不修改原状态，以及真实 8 bot 对局的确定性、输入不变性、真人锚点淘汰后继续、合法名次和完整结束。
